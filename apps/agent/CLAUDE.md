# apps/agent — Python DM agent

## Python test lanes (placement by directory)

- **Fast lane** — everything under `apps/agent/tests/` *except* `tests/acceptance/`. Run by `test:python` / `test:all` (`pytest -m "not acceptance"`). Holds pure-logic tests **and** simple real-PG tests against the shared dev DB at `:55432` — `tests/conftest.py` auto-starts docker compose if it's down (fail-loud if Docker is absent; tests are never silently skipped). Real-PG tests here isolate via unique keys + cleanup (see the `_db_lifecycle` / `dev_db_pool` pattern). Put a real-PG test here when it's a single-table / single-concern round-trip.
- **Acceptance lane** — `apps/agent/tests/acceptance/` only (marker auto-applied by directory). Run by `test:acceptance` (pre-push). **Paid provider tests (`real_llm`, `openai_real_llm`, `live_voice` markers) are always skipped** — hooks, the sprint full tier and CI included — unless a human approves a specific run: `ALLOW_PAID_TESTS=1 REQUIRE_REAL_LLM=1 uv run pytest <file>` (`tests/_paid_tests.py`, human 2026-09-22). Never put `ALLOW_PAID_TESTS` in `.env`. Per-run **testcontainer** Postgres + LiveKit dev-server. Put a test here when it's a multi-system / LiveKit / end-to-end capstone needing per-run isolation.
- **`bun run test:acceptance:nollm`** — the same lane minus the real-LLM tier (`-m "acceptance and not real_llm and not openai_real_llm and not live_voice"`). Use it when a change touches a surface the capstones cover but `test:all` excludes by design (ADR 0003) — a combat-loop change is the canonical case, since 14 capstones drive `resolve_phase`. It removes **API spend, not Docker**: the `acceptance` marker *is* "requires Docker", so this is still the testcontainer suite. Paid markers are skipped everywhere anyway; this lane also deselects them so the summary shows no skips.
