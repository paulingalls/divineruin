# Sprint 57 retrospective

The five cards shipped the M36 voice path: every active human joins from an independently authenticated app and LiveKit microphone, both players' completed speech reaches one DM, and a reaction spends the speaking player's resources during the same open combat window. Real-room tests exercised two microphones, overlapping turns, reconnects, and two distinct reaction spends. The release gate passed 84 browser tests and 306 acceptance tests, with one planned skip.

The real-room boundary caught failures that unit fakes could not: a reused microphone phrase hid a dropped transcript, RoomIO's default disconnect behavior bypassed reconnect grace, and an awaited resource lookup allowed a revoked actor to reach a write. Focused fault injections and review drove the fixes. The full acceptance lane then caught a legacy M29 `session.run()` harness that invoked a reaction without the authenticated turn binding. The focused test was red before the harness fix and green after it; the comprehensive gate passed on the corrected tree. A later full run also showed Deepgram dropping the single word "apostle" while preserving the speaker identity and the rest of the sentence; the lifecycle test now checks a distinct phrase from that transcript. This is why the older real-LLM scenario belongs at the release boundary, not in every story's Verify line.

The test tiers served different decisions. Staged language checks kept commits cheap; focused Verify covered each card's changed behavior; story close ran the unit aggregate; sprint close ran the comprehensive gate. The avoidable cost was repetition inside those boundaries: story 100's executor ran `test:all` before the required story-close run, and seven resolved work records replayed checks that the full hook also runs. The standalone resolved-record batch measured 345.7 seconds; two ownership checks alone took 313.2 seconds. Those seven records are archived after the full gate passed, removing their separate commands from future sprint closes while retaining the tests in the full hook. Constraint 7 already requires targeted Verify and excludes `test:all`; no second rule is added.

PR CI lacked a Deepgram credential and failed all six real-room voice tests at setup while the other 7,494 Python tests passed. The live-voice lane now gates itself on the credential (apps/agent/tests/acceptance/_live_voice.py): without a usable key it skips with a reason, under REQUIRE_REAL_LLM it fails loud, and CI passes the repository secret through so the same run reaches Deepgram once one is configured. The local sprint full tier remains mandatory and ran all six against Deepgram before the release PR opened.

The release review caught a cross-story gap: a guest's speech reached the DM, but non-reaction tools could still write the host's state. Ability and inventory writes now use the authenticated actor and revalidate before mutation; primary-only verbs fail closed during a guest turn. Mutation checks now red when transcriber start ownership, membership, reconnect-generation, or write-boundary guards are removed. The remaining primary-only verbs need an actor-aware migration card before guests can use the full toolset. The now-unused string actor binding can then be removed with its legacy test. Reconnect event/task histories and repeated provider-failure reports need bounded retention. The 1.0-second input endpointing floor prevents a natural pause from splitting an utterance, but it consumes much of the 1.5-second first-audio target; measure actual playtest latency before changing the floor.

The executable process change is the work-record triage: seven standalone resolved falsifiers are retired because the same tests run in the full hook. The existing focused-Verify constraint remains the rule for the next sprint.
